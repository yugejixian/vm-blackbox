# 用例 009：登录场景 + 安全链路（凭据库 / 截图遮蔽）

## 目的
验证「测试员需要输入密码」这类场景，在**密码不进模型上下文**的前提下能测通；
同时验证遮蔽链路（自动 + 手动）不会泄露、也不会过度遮蔽到无法操作。

## 前置
- 干净基线；桌面有 `login-test.html`（本地页面，无网络）。
- 宿主凭据库里有一条测试凭据：`qa_login_test`（值故意包含中文，压测 Unicode 编码链路）。
- 期望 SHA-256 = 对凭据明文做 SHA-256（宿主侧独立算出，用于比对）。

## 页面约定
`login-test.html` 提交后显示真值面板：

```
user=<账号>
pwdLen=<密码长度>
pwdSha256=<密码的 SHA-256>
otp=<验证码>
```

> 只有哈希，没有明文。若明文出现在页面上，说明应用自身不安全（本用例不涉及）。

## 步骤
1. 打开页面，截图定位三个输入框（**每次刷新后都要重新截图**：页面滚动会改变坐标）。
2. 点账号框 → `vm_type` 输入 `qa-user@example.test`。
3. 点密码框 → **`vm_type_secret("qa_login_test")`**（绝不用 `vm_type` 传密码）。
4. 点验证码框 → `vm_type` 输入 `123456`。
5. 点「登录」→ 截图。

## 通过标准
| 断言 | 期望 |
|---|---|
| 页面结果 | `LOGIN OK` |
| `pwdLen` | 与凭据长度一致（12） |
| `pwdSha256` | 与宿主侧算出的哈希**逐字符一致** |
| `user` / `otp` | 与输入一致 |
| 截图 | 密码框/验证码框为 `REDACTED` 黑块；**任何地方都看不到明文** |
| 遮蔽范围 | 只覆盖焦点控件（+ 标题条带），**不应覆盖整页** |

## 反面断言（发现过真 bug 的地方）
- **编码**：中文密码若被转码，`pwdLen`/`pwdSha256` 会对不上 → 说明「宿主→隧道→访客」链上有编码 bug。
- **过度遮蔽**：若整页变黑，说明焦点控件判定错了（Chromium 的 HWND 焦点=整个窗口，必须用 UI Automation 取真实焦点元素）。

## 残留风险
- 状态栏/长度泄漏（如 `23 characters`）；
- 应用把密码回显到别处（需 `vm_screenshot(mask=...)` 手动补遮）；
- 窗口移动/缩放后遮罩坐标失准。
