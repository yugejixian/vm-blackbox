## 代理自启（2026-10-25 修）

**不要依赖计划任务**。实测：`QaTunnel` 的 `ONLOGON + /IT + HIGHEST` 计划任务在快照恢复/冷启动后**不会留下进程**（任务显示 LastResult=0，但 `tasklist` 里没有 QaTunnel）。怀疑是 HighestAvailable 在当前 UAC 配置下静默失败。

**现在的做法**：启动文件夹快捷方式直接跑 exe（非提权）：

```
C:\Users\qa\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\QaTunnel Autostart.lnk
    → 目标：C:\qa\QaTunnel.exe    工作目录：C:\qa
```

脚本：`scripts/mk-startup.ps1`（首次创建）、`scripts/fix-startup.ps1`（改成直指 exe）。

**代价**：非提权代理无法向提权窗口（UAC 提升过的安装程序）发合成输入。需要测提权程序时再手动用计划任务拉起，并接受可能失败。

**另一个必查项**：宿主侧 `tunnel-host.js` 在宿主睡眠后不会自动恢复，访客日志会刷「积极拒绝 10.0.2.2:8801」。开测前先 `curl http://127.0.0.1:8890/status` 确认。

## 环境约定：提权不弹窗

测试机的 UAC **不弹窗、管理员进程静默提权**：

| 注册表项 | 值 | 说明 |
|---|---|---|
| `ConsentPromptBehaviorAdmin` | `0` | 管理员提权不询问 |
| `PromptOnSecureDesktop` | `0` | 不用安全桌面 |
| `EnableLUA` | `1` | UAC 本身仍启用 |

**为什么**：测试员跑在普通用户会话里，合成输入进不了安全桌面，任何需要提权的安装向导都会卡在 UAC 那一步。实测 Everything 安装包会在「安装」时弹 UAC，测试员完全点不动。

**代价**：UAC 交互本身不在自动化覆盖范围内；真实用户会看到「你要允许此应用…」这一屏。这是明确的取舍，不是遗漏。

**⚠️ 关键补充（005 踩过）**：静默提权只消除了**询问框**，没有消除**完整性边界**。进程照样提权成高完整性窗口，UIPI 照样把低完整性的合成输入整条丢弃——而且因为没有任何提示，现象看起来像「界面死了」。005 就撞在这上面：卸载器提权后输入全丢，连点其他窗口也没反应，最后靠宿主物理键盘才关掉。

**真正的解法是让代理本身高完整性运行**（见上文计划任务 `/RL HIGHEST /IT`）：高完整性进程的 SendInput 可以进高完整性窗口，这是 UIPI 允许的方向。改完之后提权向导可被正常驱动。

改动方法（已固化进 `zh-cn-clean`）：把一个 .bat 拷进访客，用 `powershell -c Start-Process C:\qa\uac-off.bat -Verb RunAs` 提权运行，宿主用物理键盘 `Tab` 到「是」再 `Space` 确认一次即可。

```powershell
& 'scripts\vm-ui.ps1' -Mode status     # 看状态（窗口/隧道）

```

- 两种模式下隧道和 `vm_*` 工具都可用，区别只是有没有一个你能看见、能点的窗口。
- 切换会先 `poweroff` 再按目标模式启动，访客未保存状态会丢；需要干净基线先 `snapshot restore`。
- 实测：`show` 与 `headless` 双向切换，从关机到隧道就绪各约 **24 秒**。
- **同时操作会打架**：你在窗口里点的时候，自动测试的合成点击也会生效。
- 脚本必须存成 **UTF-8 with BOM**，否则 PowerShell 5.1 按 ANSI 解码，中文会让引号错位、整份脚本语法失败（`build-vm.ps1` 同样处理过）。

## 文字输入：改走剪贴板粘贴（2026-10-25 修）

**现象**：逐字 `SendInput` + `KEYEVENTF_UNICODE` 注入中文时，文件里的字是错的。实测（同一串文本）：

| 输入 | 实际落盘 |
|---|---|
| `这一行是中文输入` | `中中中中中文输入` |
| `第三行：456 × 789` | `行行行：456 88889` |
| `Unicode` | `ccccode` |
| `ABC-123` | `2222223` |

不是字体缺字（码位不同），是**键盘事件被中文输入法/编辑器层改写**（未定位到具体钩子）。

**修复**：`TYPE` 改为**剪贴板粘贴**——`SetClipboardData` 写 Unicode 文本 + `Ctrl+V`；只有剪贴板失败时才回退到逐字注入（回退路径里还会临时 `ImmAssociateContext(hwnd, NULL)` 解绑输入法）。

**验证**：输入 `黑盒测试 ABC-123 中文 456 结束。`，保存后从访客拷出读字节：

```
41 字节，内容与输入完全一致
hex: e9bb91 e79b92 e6b58b e8af95 20 41 42 43 2d 31 32 33 ...
```

**代价**：粘贴是「一次性写入」，不是逐键输入。对文本框类应用没问题；如果某个应用只认按键（某些游戏、自定义控件），需要退回按键模式——那种情况要单独测。

## 敏感数据与登录场景（2026-10-25 加）
### 安全链路的两个实测 bug（2026-10-25 修）

用 `assets/login-test.html`（真值面板只显示 pwdLen 与 SHA-256）做靶子，抓到两个真问题：

1. **中文凭据被转码**：`vault-get` 子进程按系统代码页输出，Node 按 UTF-8 解码 → `测试` 变成 4 个乱码字符（长度 12→14，SHA 不等）。
   修复：脚本内 `[Console]::OutputEncoding = UTF8`，隧道 `runCapture` 改为**按字节缓冲后统一 UTF-8 解码**。
2. **Chromium 应用被整页遮蔽**：焦点窗口 = 浏览器主窗口，代理把整块当密码框。
   修复：`FocusRect()` 先用 **UI Automation**（`AutomationElement.FocusedElement.BoundingRectangle`）取真实焦点元素，失败才回退 HWND。
   副作用：遮蔽会累积（密码框 + 之前注入的验证码框各一块），180 秒后自然过期。

**验证方式**：页面提交后比对 `pwdLen` 与 `pwdSha256`——这能同时证明「密码完整到达目标」和「截图里看不到明文」。

**问题**：观察完全基于截图。测登录时密码会经两条路泄露：
① `vm_type` 的参数本身就是明文 → **直接进入模型上下文和会话记录**；
② 截图里可能出现密码框、窗口标题、地址栏 token、日志面板。

### 四层防护

**第一层 · 纪律**
- 虚拟机里**绝不放真实凭据**，只用一次性测试账号，测完禁用；
- 测试员不许对「密码框、OTP 码、带 token 的地址栏」截图；
- 这两条已写进测试员提示词模板和免责声明。

**第二层 · 凭据库（密码不进模型）**
- `scripts/vault-set.ps1 -Name qa_login` 录入（DPAPI 加密，绑定当前 Windows 用户；文件 `agent/vault.dat`）；
- 测试员只传**名字**：`vm_type_secret("qa_login")`；
- 宿主解密后经隧道发给代理注入，**返回值只有 `{ok, masked}`，模型全程看不到明文**。

**第三层 · 像素遮蔽**
- `SECRET` 之后代理记录两块区域：**焦点控件矩形 + 前台窗口标题栏条带**；
- 之后 **180 秒内每一帧**都把这两块涂黑（黑块 + 红框 + `REDACTED`），在 JPEG 编码**之前**完成；
- **宿主抓帧路径同样遮**（`RulerOverlay` 支持 `mask=x,y,w,h;...`）——这条必须做，否则 3D/陈旧帧切到宿主路径就绕过了遮蔽（实测踩过：宿主路径第一版没遮，密码明晃晃出现在截图里）；
- `vm_screenshot(mask=[{x,y,w,h}])` 还能手动指定额外区域（如 OTP 输入框）。

**第四层 · 静态数据**
- 遮蔽发生在编码/落盘之前，磁盘上的图已经打码，拷进 `runs/` 的证据同样是黑的；
- 截图目录用 `scripts/clean-shots.ps1` 定期清理。

### 已知残留风险（别当它是万能的）

| 风险 | 说明 |
|---|---|
| 长度泄漏 | 状态栏可能显示 `23 characters` 这类信息 |
| 应用自己回显 | 设置页/日志面板若明文显示密码，需要手动 `mask` |
| 窗口移动后失效 | 遮罩是**当时坐标**；窗口移动/缩放后要重新触发一次 `SECRET` |
| 剪贴板 | 粘贴后立即清空，但目标程序延迟读取仍有理论窗口 |
| 宿主路径时序 | 遮罩生效前已抓的旧帧不受影响（无缓存，但依赖时序） |

## 合成光标（2026-10-25 加）

**问题**：抓屏里从来没有光标。原因是 VirtualBox 的鼠标光标由**宿主层**绘制，GDI 抓屏和 `screenshotpng` 帧缓冲都拿不到它——所以围观者只看到画面在变，看不到「指针走过去」。

**做法**：

1. 代理新增 `CURSOR` 操作，返回当前指针坐标（`GetCursorPos`）；
2. 隧道每抓一帧，就查一次指针位置并传给 `RulerOverlay`：
   - 宿主抓帧路径：标尺 + 点击准星 + **合成光标**一起画；
   - 访客抓帧路径：加 `noruler`，只叠合成光标；
3. 合成光标画成白色箭头 + 黄色圆环，和青色点击准星（十字）区分开；
4. `MoveTo` 改成**分步移动**（按距离自适应，约 350ms 走完），看板刷新 450ms（约 2.2 帧/秒）——这样能看出指针从哪划过来。

**限制**：

- 帧率仍只有 ~2 帧/秒，快速连续点击只能看到跳点，不是流畅动画；
- 合成光标是**示意**，不等于系统真实光标外观（某些应用会改光标形状，这里看不出来）；
- `CURSOR` 每帧多一次往返（约 1–3ms），可忽略。

## 陈旧帧检测（2026-10-25 修）

访客代理用 GDI 抓屏，**抓不到 D3D/Unity 这类 3D 窗口**——但它不报错，而是返回上一帧桌面。测试员会以为游戏没启动（这就是 10/24 演示时踩的坑）。

**现在的判据**（在 `tunnel-host.js` 的 `/shot` 里）：

1. 访客帧与上一张**完全相同** → 顺手抓一张宿主帧缓冲；
2. 宿主帧**变了** → 判定访客陈旧，切到宿主抓帧，保持 60 秒；
3. 响应头 `X-Shot-Via: host` 标明来源，插件在工具返回文案里写 `capture=host`。

**限制**：如果 3D 画面本身静止不动（例如停在静态菜单），宿主帧也不变，就不会触发——此时可手动加 `?src=host` 强制宿主抓帧。

## 坐标标尺（截图自带坐标系）

`vm_screenshot` 返回的图上有**红色标尺**：每 200 像素一条细线，顶部/底部/左右边缘标着数字，**数字就是屏幕真实像素坐标**。

- 测试员点按钮时，直接读标尺数字给 `vm_click`，不需要任何换算。
- **青色十字 + `click x,y` 标签是上一次点击的落点**。点完再截一张图：如果十字没落在目标上，就是坐标读错了——重新读标尺，不要自己乘系数。
- 标尺是工具画的，不是界面的一部分；提示词里必须写明这一点，否则测试员会把它当成 UI 元素。
- 1000 的倍数那条线更粗，方便快速定位。
- 需要无标尺的干净图时，隧道支持 `SHOT <q> plain`（目前插件没暴露这个开关）。

**为什么要有它**：模型看到的截图会被图像管线缩放到 1708×961（1920×1080 的 0.8896 倍），但 `vm_click` 收的是原生坐标。测试员照缩小图读数、原样传进去，落点就会偏上偏左约 11%——前几轮「按钮点不动」全是这个原因，不是权限、也不是产品缺陷。

**但坐标问题的另一半在用例侧**：UI 会因内容变化而重排。Windows 计算器显示表达式行（`12 + 7 =`）时显示区变高，整个按钮网格**下移约 54px**，清空后又缩回。拿重排前的截图坐标去点重排后的界面，就会点到相邻按钮（实测把「C」点成「√x」两次）。

**输入映射本身是精确的**：`agent\Calibrate.exe` 全屏标定 9 个已知点，落点与请求**逐点相同（9/9，0px 误差）**。所以坐标问题的两个真实来源只有：
1. 用了预览图坐标没换算（×1.1241）；
2. 界面重排后复用旧坐标。

**规矩**：每次点击前重新截图；坐标只用「当前这张图」上的标尺数字。

## 跑用例的铁律（防假阳性）

1. 用例前置必须验证：目标文档是**空白新文档**（`Untitled` / `Ln 1 Col 1` / `0 characters`）。会话恢复出来的旧内容不能当通过证据；遇到脏基线就新建空白标签并说明。
2. **子代理返回之前不读日志、源码或任何后台数据。**
3. 返回后先用 `read_image` 逐张核对它引用的截图。
4. **再调子会话的工具调用日志做全量核对**：把它的实际动作序列和报告里写的步骤对一遍，找出报告没写的动作（误点、多余窗口、未声明的副作用）。报告是摘要，日志才是事实。
5. 核对完成后才允许做后台诊断。
6. 报告写 `D:\null_work\runs\<run-id>\report.md`。
7. **收尾前跑一次体检**：`& 'scripts\check-run.ps1' -All`
   - 硬性：报告存在、有明确结论（PASS/FAIL/被阻断）、**每个引用的截图都在磁盘上**
   - 软性：缺「步骤/可疑项/取证」措辞、磁盘上有没被引用的孤儿图
   - 实测价值：第一次跑就在 `case002b` 里抓到一张引用了但不存在的截图——那张收尾图其实在全局 `D:\null_work\shots\` 里，没归档进运行目录。收尾截图也要落进 `runs\<run-id>\shots\`。

## 踩过的坑（都在这里了）

- **安装完必须摘 ISO、`boot1=disk`，并正常关机**（`shutdown /s /f`）。否则一重启就又从光盘进安装程序；硬断电还会留下未完成的安装，重启后续装，把已装好的系统覆盖掉。
- **不要在等待启动时连按 Enter**：按键会被 Windows 消息队列缓冲，程序窗口一创建就连续消费，直接把开场/菜单"点掉"（006 实测：开场画面和主菜单一张没拍到）。正确做法是**等窗口出现后再按键**，等待期间只截图。
- **合成双击对桌面 `.exe`/`.lnk` 不触发启动**（对文件夹、回收站有效）。实测：双击安装包等 17 秒无反应，前后两张截图逐字节相同；换位置再试仍无效。
  **标准动作：打开项目一律「单击选中 + Enter」。** 这条已写进测试员提示词，用例里写「双击」时按等价动作执行并在报告里注明。
- **设置应用里的「…」弹出按钮点不动**（005 实测连点 3 次无效），要 `Tab` 凑到再按 `Enter` 才生效；但**安装/卸载向导里的按钮直接点就行**。别一刀切说「按钮都点不动」。
- **隧道的 SendInput 进不了高完整性窗口**（UAC、管理员 CMD）——那些场景要用 `VBoxManage controlvm keyboardputstring / keyboardputscancode` 的物理键盘。
- **物理键盘打不出双引号**；带空格的路径改用 PowerShell 单引号写法。
- **`C:\` 根目录只能建目录、不能建文件**；临时脚本放 `%TEMP%`。
- **宿主 Defender 的 AMSI 会拦 `iex(iwr …)` 模式**；改成先 `curl -o` 落盘，再 `powershell -File` 执行。
- 宿主文件服务 `0.0.0.0:8800`（`python -m http.server`，目录 `D:\null_work\agent`）只在装/更新代理时需要，平时可以关。
- 提权配方：`win+r` → `powershell -c "Start-Process cmd -Verb RunAs"` → 物理键盘 `Tab Tab 空格`（焦点顺序 No → Show more details → Yes）。
